# Architecture Decision Records (ADRs)

This directory records the technical decisions behind Project Dogwood — what was chosen,
why, what it assumes, and which specifications changed as a result.

## Organization

ADRs are grouped by the layer they affect:

```
adrs/
  layer-1/ADR-001-example.md
  layer-2/ADR-001-example.md
  ...
```

A decision that spans several layers is filed under the layer it most affects, and links to
the others from its **Updated Documents** section.

## When an ADR Is Required

Drafting the initial specifications did not require ADRs. That phase is over. From here on,
**any technical decision, pivot, or resolved assumption requires one** — see `AGENTS.md` §3.

An ADR is valid only when it lists every specification document updated as a result of the
decision. Traceability is the point: a reader should be able to start at any line in a
specification and find the decision that put it there.

## Template

Copy the template from [`AGENTS.md`](../AGENTS.md) §3. It covers: Context & Problem
Statement, Decision, Rationale & Research (with links proving feasibility), Unstated
Assumptions, and Updated Documents.

## Index

### Layer 2 — Server Compiler
- [ADR-001: Kotlin/Wasm Requires WebAssembly Garbage Collection (WasmGC) on Every Target](layer-2/ADR-001-kotlin-wasm-requires-wasmgc.md) — **Accepted.** `wasmWasi` is not a linear-memory target; there is no opt-out and no fallback. Removes Wasm3 from consideration.
- [ADR-002: Replace Compose Call Interception with a Generated Stub API](layer-2/ADR-002-generated-stub-api-replaces-ir-interception.md) — **Proposed.** `@Composable` and `external` are mutually exclusive and the core layouts are `inline`. Guests compile against generated stubs instead.

### Layer 4 — Sandbox Engine
- [ADR-001: Reject WebAssembly Dynamic Linking (`dylink.0`)](layer-4/ADR-001-reject-dylink-dynamic-linking.md) — **Accepted, now moot.** Linking Wasm against native ARM code is a category error.
- [ADR-002: Adopt Kotlin/JS on QuickJS (Zipline); Reject WebAssembly](layer-4/ADR-002-adopt-zipline-quickjs-substrate.md) — **Accepted.** The boundary costs 0.2-0.5% of a frame either way; WasmGC forces the slowest interpreter; `@WasmImport` cannot express the bridge. Batching, not the engine, is what matters.
- [ADR-003: Redwood Treehouse Is the Existence Proof; External Evidence Refresh](layer-4/ADR-003-treehouse-precedent-and-evidence-refresh.md) — **Accepted.** Compose composition verifiably ran in Zipline's QuickJS (Treehouse samples + limited production); Phase 0.2 becomes a measurement question with a cheaper start. Redwood's shutdown publicly characterised as non-technical. App Store analysis re-anchored on Guideline 4.7. Compose Multiplatform: iOS Stable, Web Beta. Hermes recorded as the fallback substrate.
- [ADR-004: The `Change`/`Event` Protocol Shape (Provisional v0)](layer-4/ADR-004-change-event-protocol-v0.md) — **Proposed.** Field-by-field schema, 8-bit-segment tag encoding, batch/event sequence numbers, absence-as-default sentinel, a worked wire example, and the minimal Phase 1 entry-point contract. Binding for Phase 0.3 and Phase 1.
- [ADR-005: Phase 0 Harness Resolutions — Reference Screen Size, Event Handlers, and Stack Size](layer-4/ADR-005-phase-0-harness-resolutions.md) — **Accepted.** The harness appendix's "50 rows" and "~160 nodes" cannot both hold; the reference screen is **23 rows** (exactly 160 widget nodes) with 50 rows measured as a second point. Chip selection derives from `quantity` so the holder count stays at 24; the per-row handler is an `onClick` parameter standing in for `Modifier.clickable`. Corrects Layer 4's stack figure: `Zipline.create` raises `maxStackSize` to **6 MiB**, so 512 KiB is not what a host inherits.
- [ADR-006: The Batch Crossing Is Guest-Side Encoding, Not Transport](layer-4/ADR-006-batch-crossing-is-guest-encoding.md) — **Proposed.** Phase 0.3 measured: the 572-change initial batch crosses in **24.06 ms**, of which **99.4% is guest-side encoding** and 1% is transport — six times the 4 ms gate leg, on hardware faster than the gate device. Reaching QuickJS's native `JSON.stringify` (which Zipline already does) is worth 47%; array polymorphism is worth 3%. A binary wire format is **not** the available escape hatch, because `CallChannel` is string-typed. The gate leg's reading is escalated, not renegotiated.
- [ADR-007: The v1 Wire Format Is Positional JSON Built as Native JavaScript Values; Binary Encodings Are Rejected](layer-4/ADR-007-v1-wire-format-positional-json.md) — **Accepted.** A bake-off over six encodings of the same batch. Positional JSON built as native JavaScript values and handed to QuickJS's own `JSON.stringify` crosses in **1.23 ms against 24.02 ms — 95% less**, confirmed at roughly 17× on a Pixel 10 Pro. Protocol buffers (+45%) and CBOR (+908%) **rejected on measurement**: their encoders are pure Kotlin and run interpreted, and a string channel forces a Base64 surcharge that leaves protocol buffers larger on the wire as well as slower. Modifier-chain interning **rejected** — 7% fewer bytes, 31% longer. Host decode measured at 0.17 ms, so the complete positional path is ≈ 1.4 ms against ≈ 24.2 ms today. Withdraws ADR-006's "cost is linear in bytes": the governing variable is how much interpreted Kotlin runs while encoding.
- [ADR-008: Phase 0's Gate Will Not Be Closed on the Named Device](layer-4/ADR-008-gate-device-not-available.md) — **Accepted.** No low-end device is available and none will be acquired, so the gate is formally not closed and work proceeds with the shortfall carried as a standing risk. The risk is **0.2, recomposition**, not the 0.3 that had the attention: 1.58 ms at p95 against 8 ms, comfortable at a three-times-slower core and at the edge at five. Discharged by the first real deployment, not by a purchase.

### Layer 5 — Native Host
- [ADR-001: Compose Runs Natively on the Host](layer-5/ADR-001-host-native-compose-owns-semantics-and-input.md) — **Accepted, corrected.** Resolves the contradiction between section 1 and section 8.3 of the overview. Accessibility is inherited from Compose Multiplatform; the text-input half of the original conclusion was withdrawn after review — text input is bespoke subsystem 3.
- [ADR-002: Standalone FIR Codegen Tool, Not KSP](layer-5/ADR-002-standalone-codegen-tool-not-ksp.md) — **Proposed.** Neither Zipline nor Redwood uses KSP for its bridge. Adopts Redwood's embedded-frontend + KotlinPoet pipeline generating both ends from one source.
- [ADR-004: Compose Multiplatform Is the Sole Host Rendering Target](layer-5/ADR-004-compose-multiplatform-sole-host-target.md) — **Accepted.** Redwood ships 4 host implementations per widget set; one Compose Multiplatform target reaches Android, Web (Beta), and iOS with one generated binding, in the roadmap's platform order. Requires the host app to be a Compose Multiplatform app, and records the costs: ~9 MB on iOS, Skia rendering rather than native widgets, and an organisational ask that amplifies Redwood's reported adoption failure.
- [ADR-003: Opaque Handle Binding Surface](layer-5/ADR-003-opaque-handle-binding-surface.md) — **Proposed; measurement superseded by ADR-005.** The opaque-handle model and the published-dictionary decision stand; its coverage figures are withdrawn.
- [ADR-005: Corrected Coverage Measurement (Third Revision) and the Re-Enumerated Bespoke Subsystem List](layer-5/ADR-005-corrected-coverage-and-bespoke-subsystem-list.md) — **Accepted.** 445 widget-shaped composables: 67.6% generable after `Modifier` (76.4% of those also need the deferred-expression protocol), 25.2% bespoke, 7.2% unreachable; a 458-function lowercase surface reported separately. The bespoke list grows from six to **nine**: animation, resources & assets, and host services/entry points/host-registered components are added.
- [ADR-006: Guest-Composed vs Host-Registered Components, Multi-Design-System Registration, and the Design-System-First Adoption Path](layer-5/ADR-006-guest-composed-vs-host-registered-and-multi-design-system.md) — **Accepted.** Developer-defined composables are plain Compose: no dictionary entry, no host release, no skew surface. A component is bridged only if its implementation must live host-side. The dictionary is segmented so any number of design systems register independently; registered components absorb bespoke subsystems; generator v1 targets registered modules + `foundation-layout`, Material tier is v2. Sets the roadmap's design-system-first sequencing and Android → Web → iOS platform order.
- [ADR-007: Keep the Snapshot Mirror; Reject the Imperative Applier](layer-5/ADR-007-keep-the-snapshot-mirror.md) — **Accepted.** Both strategies built behind a shared `WidgetView` interface and measured at batch sizes 1 / 10 / 100 / 1,000 on trees of 160 and 1,222 nodes. The imperative applier applies two to four times faster, and it does not matter: the saving is ~70 µs against 1.14 ms of guest-side encoding. It recomposes **801 bindings for a one-property change** on a 1,222-node tree where the snapshot mirror recomposes **one** — per-frame work proportional to tree size rather than to change size. No tested cell separated them on latency, so the decision rests on scaling rather than on a measured failure, and says so.
- [ADR-008: The Registered Design System Is Audited Against Skyscanner Backpack](layer-5/ADR-008-design-system-audit-backpack.md) — **Accepted.** The Phase 1 step-1 audit, performed against a real, public, actively released, atomic-design system that ships Jetpack Compose components. **Five of eleven bind as declared** — including `BpkPrice`, with four strings, three tokens and a click. All three predicted failure classes appeared (`Painter`, `interactionSource`, style objects) plus **two the specification did not name**: a lambda the host invokes to obtain a value, and an indexed content lambda. The carousel is the load-bearing finding — lazy layouts cannot be absorbed by registering a component the way images and animation could.
- [ADR-009: The `Modifier` Subsystem — Tag Space, Ordering, and Scope as a Build Error](layer-5/ADR-009-modifier-subsystem.md) — **Accepted.** Segment-encoded tag space, chains as ordered sequences, immutable `then()` with structural equality. Out-of-scope `weight`/`align` is not merely diagnosed but **unwritable**: they are members of guest scope receivers supplied by each container, which is the mechanism Compose itself uses. Pixel identity is explicitly *not* asserted; the protocol half is.
- [ADR-010: The Deferred-Expression Grammar](layer-5/ADR-010-deferred-expression-grammar.md) — **Accepted for modifier arguments; the general case scoped but unbuilt.** An expression is a recipe, `[factory, arg, …]`, evaluated host-side with a bounded memo, degrading on unknown factories rather than throwing. Named colour tokens are the point: the guest names an intent and the host resolves it in theme, which a literal cannot. Caught a real encoder bug on first run — structured values were being stringified into JSON that still parsed and was entirely wrong.
- [ADR-011: The Generator Emits the Bridge, Not the Widget; Tags Are Locked](layer-5/ADR-011-generator-emits-the-bridge.md) — **Accepted for generator v1.** From one parsed surface: guest stubs, host dispatch, and the versioned dictionary. The dispatch calls a hand-written implementation, because a generator cannot invent visual design and the part that grows without bound is the dispatch, not the design. **Nine of eleven registered components are now bound with no hand-written dispatch on either side**, the forty existing tests pass unchanged, and the screen renders identically. Tags are locked against a committed file and the build fails on a renumbering, because a moved tag renders the *wrong* widget rather than none.
- [ADR-012: The Host Environment Subsystem](layer-5/ADR-012-host-environment-subsystem.md) — **Accepted.** The first of Phase 4's nine bespoke subsystems. Derived in host composition from Compose Multiplatform ambients (so the derivation is common code), pushed across a dispatcher-asserted crossing, and deduplicated on both sides so a host can offer it liberally. `BoxWithConstraints` measures the slot rather than the screen, because screen metrics are wrong in split screen, on foldables, in resizable windows and in side panes — and wrong silently. `Palette` becomes a value with `Light`/`Dark` instances, which is what finally makes ADR-010's colour tokens do the thing they exist for. Verified live on the emulator: rotation re-lays out the guest with **zero** reloads and no lost state.
- [ADR-013: Host Services and Entry Points](layer-5/ADR-013-host-services-and-entry-points.md) — **Accepted.** Named entry points with serializable launch parameters, and a service vendor handed to the guest rather than looked up by it: every service optional, absence normal, resolved once because each accessor call allocates a proxy pair. The network service is `suspend` by necessity and its host implementation **defaults to refusing every request** — a payload replaceable over the air must not reach arbitrary addresses through the application's network stack. Uncovered a Layer 4 gap and closed it: until services existed, every guest state change began with a host call, so a suspending call's resumption wrote state with nobody left to notice — the first fetch logged a parsed feed while the screen sat on "Loading…".
- [ADR-014: Live-State Holders](layer-5/ADR-014-live-state-holders.md) — **Accepted.** The constructive half of Layer 4's no-per-frame-state invariant, established on `LazyListState` and meant to carry the other ~29 holders. Reads are reports, item-granular rather than pixel-granular; writes are declared targets crossing as ordinary properties, so the conflict rule needs no enforcement — a property carries only its latest value, so the newest target wins and a stale one cannot arrive. Scroll position survives a code update. **A device produced the finding reasoning did not**: the restored position was saved, restored, and still lost, because a replacement guest declares its target while its content is still being fetched and `scrollToItem` clamped to a two-item list. Targets are now held until the list can satisfy them.
- [ADR-015: Node Identity and Reuse](layer-5/ADR-015-node-identity-and-reuse.md) — **Accepted.** The mechanism was already built; the test was not, because nothing could run a host composition off a device. `compose.uiTest` now runs one in the ordinary unit-test suite, and `DogwoodSurface` was split so a `HostTree` renders without a Zipline instance. Three findings, two of them invisible to reading: the first version of the test asserted nothing (`ChildMove(0, 1, 1)` is a no-op under Compose's move convention); a headless composition has no global snapshot manager, so mutations never reach it; and — the one worth the exercise — **`key` is silently defeated by a per-child conditional**, because a movable group can only be matched among its immediate siblings. Nothing warns and the screen still renders correctly. Also closes ADR-009's open claim that modifier order affects layout: 48 against 32.
- [ADR-016: Leak Detection](layer-5/ADR-016-leak-detection.md) — **Accepted.** `redwood-leak-detector` adopted as the roadmap says, wrapped behind `DogwoodLeakWatcher` because Redwood marks the type "for Redwood internal use only" and the project is discontinued. Aimed at the two places this architecture leaks: a detached subtree, and a replaced guest generation — which is not one stale object but a Zipline instance and an entire QuickJS heap. **It found a real defect on its first run.** A code update reuses the same node identifiers, so `key(node.id)` matches the same composition groups and a `LaunchedEffect` keyed on anything tree-stable is never restarted; the lazy list's viewport reporter kept the first `EventSink` and was still reporting to the previous, closed guest. The memory was the smaller half. Fixed with `rememberUpdatedState`, with a regression test verified non-vacuous.
- [ADR-017: Resources and Assets](layer-5/ADR-017-resources-and-assets.md) — **Accepted.** One pattern applied four times: the guest names an intent, the host owns the meaning. Icon dictionary, typography tokens (which are the font story), payload-carried string tables, and — the piece the original enumeration missed — **locale-aware formatting as deferred expressions rather than a service**, because formatting is needed during composition and six prices would otherwise be six suspending crossings before anything could be drawn. Money crosses as minor units and a currency code, since the host is the side that knows `JPY` has no decimal places. All skew now lands in one readable `SkewReport`. Found a generator defect: adding `Icon` took the local tag `VerticalList` already owned, and the generated dispatch runs first, so every list would have rendered as an icon — segments can now reserve tags, and the lock fails a collision, a withdrawn reservation, or an addition without a version bump.
- [ADR-018: Lazy Layouts](layer-5/ADR-018-lazy-layouts.md) — **Accepted.** The guest composes a *window*; the host renders the true length, from an item count, a window offset, and one placeholder template composed once and repeated. **Identity is the index, not the node** — a deliberate departure from ADR-015, because in a windowed list item five hundred is item five hundred whichever guest node currently represents it, and keying on the node would rebuild every visible row each time the window slid. Sliding by one therefore costs one removal and one insertion, asserted rather than assumed. Overscan is the guest's choice of how much latency to hide, and windowing is opt-in so a six-item list pays nothing for it.
- [ADR-019: Text Input](layer-5/ADR-019-text-input.md) — **Accepted.** The host owns the text; the guest holds a version-stamped mirror and a value stamped behind the host's edit count is discarded, because the user has typed since. A version rather than "the host always wins", or `clear()` would be impossible. The one holder that cannot use ADR-014's level-triggered pattern: a stale scroll target is a wish to override, a stale text value would delete a character the user just typed. Masks, limits and counters are declared once and applied host-side. **The device found a bug the harness could not** — with the mask applied to the field's value, the caret arithmetic was the binding's and typing sixteen digits produced transposed ones; `performTextInput` does not go through an input method, so only a real keyboard reproduced it. Fixed with a `VisualTransformation`, and the regression test is on the offset mapping rather than the symptom.
- [ADR-020: Animation](layer-5/ADR-020-animation.md) — **Accepted.** The last of Phase 4's nine. An animated modifier argument is a **declared target** with a named spec; the host resolves it with `animateFloatAsState`, so a whole animation costs one crossing whatever its duration. **Interruption semantics are inherited rather than invented** — retargeting from the current value is what Compose already does when a target changes, and a "start an animation" message would have had to define that rule and got it wrong. Completions ride the element's position in the chain, and a retarget is deliberately not a completion. Layer 1's rejection of the `animate*` APIs becomes permanent rather than temporary. Exposed a bug present since ADR-011: the generated dispatch built the modifier chain before checking the tag, so every layout primitive built its chain twice — wasteful for numbers, two animations and two completion events for a target.
- [ADR-021: Host-Resolved Values](layer-5/ADR-021-host-resolved-values.md) — **Accepted.** `TextValue`, `Color` and `Shape` become one family with one rule: the guest names an intent, the host resolves it, and the emitter has a single rule to follow rather than a special case per type. Dropped the `Dogwood` prefix the user pushed back on. The lock gained a check the rename proved necessary — widening a parameter from `String` to `TextValue` is invisible to a version comparison, and an older client reading a recipe with a primitive reader would blank every price.
- [ADR-022: Animated Colour and Repetition](layer-5/ADR-022-animated-colour-and-repetition.md) — **Accepted.** Extends ADR-020's declared-target grammar to colour and to indefinite motion. A spike killed the obvious design: a repeating spec on `animateFloatAsState` silently does nothing, because it moves only when the *target* changes, so repetition needs an explicit `from`/`to` range and `rememberInfiniteTransition`.
- [ADR-023: Enter and Exit](layer-5/ADR-023-enter-and-exit.md) — **Accepted.** A node that is leaving must outlive the guest's decision to remove it, so the guest keeps two sets — what the user dismissed, and what has finished animating away — and the host reports the transition's end. A `Presence` that starts hidden fired `onExited` on its first frame until the binding tracked whether it had ever been visible.
- [ADR-024: Configurable Formatting and Plurals](layer-5/ADR-024-configurable-formatting-and-plurals.md) — **Accepted.** QuickJS ships no ECMA-402 `Intl`, so every formatted number crosses as a number and is formatted by the host. Patterns the platform will not accept are rejected into the `SkewReport` rather than thrown, and a plural category the payload carried no template for is reported rather than rendered blank. Desktop plural categories remain English-only, and that limit is stated rather than hidden.
- [ADR-025: Where a Colour Decision Lives](layer-5/ADR-025-where-a-colour-decision-lives.md) — **Accepted.** Two paths, decided after the user pushed back that a token contract is "a slippery slope to a contract that has to match on the client". Design-system components take tokens; anything else may send a literal colour. **Logic does not cross the wire** — the host injects the environment into the guest instead, so a guest decides for itself and sends a finished value.
- [ADR-026: The Theme Is a Document](layer-5/ADR-026-the-theme-is-a-document.md) — **Accepted.** A whole theme arrives as JSON, over HTTPS, with field-by-field fallback so a malformed entry costs one colour rather than the screen. Deliberately unsigned: payloads are signed because they are code, and a theme is data whose worst case is ugliness.
- [ADR-027: The Host Shell and Warm Experiences](layer-5/ADR-027-the-host-shell-and-warm-experiences.md) — **Accepted.** Phase 4.5's centrepiece. A host-side pool keeps recently used experiences alive, so switching between separately deployed guests costs **0 ms of shell time, taken synchronously**, instead of 140–650 ms of cold start; eviction snapshots state and restores it on return, riding the code-update machinery. Measured on device: 9–14 MB per warm experience, and **zero** frame requests from hidden ones over twenty idle seconds. Two defects found by running it — an eviction that cancelled a coroutine but never closed the interpreter, freeing nothing, and `rememberSaveableStateHolder` state that could not cross the boundary **at all**, taking every unrelated screen's state down with it.
- [ADR-028: Guest-Initiated Navigation](layer-5/ADR-028-guest-initiated-navigation.md) — **Accepted.** A guest can ask to go somewhere; the host interprets routes and the guest learns neither the destination nor the outcome, because that is chrome. A guest asks `canNavigate` *before drawing*, since a dead control makes the user blame the product rather than the build, and an empty route set means "this host does not enumerate", never "handles nothing". The first change to need the service-surface version gate, which is checked before the call rather than caught around it.
- [ADR-029: A Null Service Cannot Cross](layer-5/ADR-029-a-null-service-cannot-cross.md) — **Accepted.** "Every service is optional and its absence is normal" was documented from ADR-013 onward and **had never worked**: Zipline picks the service serializer with `isSubtypeOfClass`, which ignores nullability, so a null service throws at the boundary and takes the experience down at `start`. It survived because every host in the repository wired every service, until the Path B reference example did not. A guest now consults `available()` before calling any accessor.
- [ADR-030: What a Compose Multiplatform Web Page Actually Weighs](layer-5/ADR-030-web-page-weight-measured.md) — **Accepted.** Phase 5's page-weight gate, measured rather than quoted: **10.23 MB raw, 2.92 MB brotli**, of which **81% is `skiko.wasm`**, a prebuilt artifact no amount of Dogwood code discipline shrinks. Page weight is a fixed entry toll, not something that scales with the product. It does not block Phase 5; **time to first frame is unmeasured and does**, and the two plausible shortcuts both produce numbers wrong in the direction that flatters the result.
- [ADR-031: Safety-Relevant Parameters](layer-5/ADR-031-safety-relevant-parameters.md) — **Accepted.** Section 6 of the specification has required this since the first draft, in the imperative, and it had never been implemented: `safetyRelevant` existed in the specification and nowhere in the code, while the generated binding did the opposite — `enabled = node.boolean(2, true)` defaulted an absent affordance to *enabled*. A widget that owns an affordance is now **withheld** rather than drawn when it arrives carrying a property this client cannot read. **The decision is per widget, not per property**, because a client meeting an unknown tag cannot ask what that property meant; and the marking follows what a parameter governs rather than what it is called, so `Badge.selected` is deliberately unmarked where `Chip.selected` is not. Also caught a hand-written `segmentVersions` literal that had already drifted from the generated dictionary.
- [Layer 3 ADR-001: Key Rotation, Rehearsed](layer-3/ADR-001-key-rotation-rehearsed.md) — **Accepted.** Milestone 4 of the delivery layer, which its own specification said must happen "before the first production payload ships" and which had never been exercised: every test built a verifier with one key, and one of them actively asserted the manifest carried exactly one signature, so the first real rotation would have failed the suite before it failed anything else. The slice now ships two signatures and both hosts trust both, permanently, because a path exercised by every run of the sample is stronger than one exercised by a test someone might delete. Two verifier properties measured rather than quoted: **signature order decides which key a client trusting both actually uses**, and a recognised key name that fails **rejects rather than falling through** to a later signature.

- [Layer 4 ADR-009: One Grammar, One Copy](layer-4/ADR-009-one-grammar-one-copy.md) — **Accepted.** Dogwood locked its vocabulary and left its grammar unlocked. The wire discriminators were written five times with nothing comparing them, no source imported both the encoder and the decoder, and the decoder indexed positionally with no arity check — so a payload whose tuples shifted by one parsed perfectly and meant something else, with no exception and no report entry. Since the guest ships over the air independently of the host, that skew is the normal case. The grammar now lives once in `dogwood-protocol`; the encoder deliberately stays in the guest, because ADR-007 requires native JavaScript arrays for QuickJS's own `JSON.stringify`. Arity is checked, and an undecodable batch is **rejected whole, reported, and survived** — the tree on screen keeps rendering — because the changes in a batch are ordered and interdependent and there is nothing to degrade to. Deleting the third decoder turned every guest test that reads a batch into a round-trip test. Also consolidates the expression-factory and modifier identifier spaces, records withdrawn identifier 13, and closes the lock's blindness to event signatures.

- [Layer 4 ADR-010: State That Outlives the Process](layer-4/ADR-010-state-that-outlives-the-process.md) — **Accepted.** Code updates and evictions both carried guest state, and both died with the process, so a user who backgrounded a half-typed form and came back found it empty. Snapshots now persist from `onStop` — not `onSaveInstanceState`, which is synchronous while reading a live guest's state is not. **Persisting a snapshot changes what a snapshot is**: measured at 71 bytes, and containing the plain-text digits of a masked card-number field, so the store is bounded, deleted on read, private, and a guest can decline with `rememberTextFieldState(sensitive = true)`. Three bugs found by looking at a screen rather than a log, all of which reported success: the host forgot which tab it was on, the store was consumed inside a subcomposition that restarts, and `DisposableEffect` closed the shell it had just built.

- [ADR-032: The Web Profile](layer-5/ADR-032-the-web-profile.md) — **Accepted.** Phase 5's gating design, decided on three measurements rather than on taste. The guest is ordinary JavaScript in a **Web Worker** — not the simpler same-thread option, because a blocking guest there is a dead tab rather than a stuck screen, and because collapsed onto one thread the existing threading assertions would still run and mean nothing. The bridge is `postMessage` carrying the **unchanged** positional protocol; the measured transport is 0.02% of a frame, and the cost split inverts so that *decoding* becomes the larger half on web. The dictionary check moves to a sidecar manifest verified before the Worker exists. Isolation is the Worker plus a Content Security Policy, and the specification's sandbox claim is **amended** to say it is weaker on web rather than left to imply parity. Integrity is named as the gap: HTTPS authenticates the server but does not give what manifest signing gives. `--gufa` is dropped from the `wasm-opt` pass list, with a correctness gate, because the toolchain silently miscompiles `String.toCharArray()`.

- [ADR-033: The iOS Host Profile](layer-5/ADR-033-the-ios-host-profile.md) — **Accepted.** The record Phase 6 owed: iOS runs the same host on Kotlin/Native with four platform-shaped differences — a dedicated `NSThread` at 8 MB because Apple's 512 KiB default overflows QuickJS composition, `UrlSessionNetwork` in place of OkHttp, platform clock and formatting, and storage rules that reopened ADR-010 since everything outside `Caches/` is iCloud-backed. Written after the adversarial review, so it records what iOS does rather than what the first attempt did — including that the network transliteration kept the shape and lost the teeth in three ways, and that `Shell.evict()` closed a guest from the wrong thread, which the Java Virtual Machine tolerated and Kotlin/Native aborts on. **Tolerated is not correct**: Android had been racing on the guest heap during every eviction. The generalisable lesson is that a security boundary ported without its tests is a boundary ported without its guarantees.

- [ADR-034: Images Are a Network Channel](layer-5/ADR-034-images-are-a-network-channel.md) — **Accepted.** `DogwoodNetwork` default-denies, caps bodies and re-checks redirects because the payload is replaceable over the air — and none of it applied to images. `AsyncImage(url)` reached whatever the guest named, so a payload could exfiltrate through a URL alone without ever calling `fetch`: **making the request is the leak**, and the response is not even interesting. Images now get their own default-deny rule rather than sharing the data one, because a content delivery network should be able to serve pictures without also being allowed to answer data requests — one list would push hosts to widen the *data* policy to accommodate pictures. Enforced by an interceptor that short-circuits before a connection opens, and verified on device, which is the part no unit test can show.

- [ADR-035: Hostile Property Values Are Clamped and Reported, Not Thrown](layer-5/ADR-035-hostile-property-values.md) — **Accepted.** Compose enforces some numeric ranges by throwing, and the throw lands *inside composition* — so an off-by-one in a payload delivered over the air without a store review is not a degraded screen but no screen, on every client that receives it, at the same moment. Values are clamped at the reader layer and the clamp is reported in `SkewReport.clampedValues`, so a designer wondering why their spacing was ignored finds the answer in a report rather than a debugger. States its own limit plainly: hand-written clamps protect the properties somebody thought of. **[ADR-042](layer-5/ADR-042-ranges-are-declared-on-the-surface.md) closes that.**

- [ADR-037: Plural Rules Are Vendored, and Checked Against ICU](layer-5/ADR-037-plural-rules-are-vendored.md) — **Accepted.** The CLDR cardinal rules for ~180 language subtags, vendored into common code and **verified against ICU4J in a test rather than trusted**. iOS uses it as its whole implementation, the desktop Java Virtual Machine falls back to it, and Android still prefers the platform's own rules. Tractable because `pluralCategory` takes an `Int`: the CLDR operands collapse when there is no fractional part.

- [ADR-038: The Web Profile's First Frame Is Transfer-Bound](layer-5/ADR-038-first-frame-is-transfer-bound.md) — **Accepted.** Measured rather than argued: headless Chrome over the DevTools Protocol, Chrome's own network emulation, ten cold loads per preset with a fresh context each time, reading the shipped page's own `firstFrameMs`. The first frame is **transfer-bound** — the number moves with the connection and barely with the machine — which is what makes page weight the lever and everything else noise around it.

- [ADR-039: Accessibility Is Asserted, Not Inspected](layer-5/ADR-039-accessibility-is-asserted-not-inspected.md) — **Accepted.** VoiceOver does not read a screen; it reads the `UIAccessibility` surface and acts on it through ordinary public Objective-C methods — so **anything VoiceOver can invoke, a test can invoke**, and the result is observable in the same tree. The drill asserts in a gate that fails rather than printing a report somebody reads once, and is precise about the half it does not cover: what the platform *announces* is not what an assertion can see.

- [ADR-040: Conformance Is a Catalogue and a Grammar, Not a Shared Test Suite](layer-5/ADR-040-conformance-is-a-catalogue-not-a-suite.md) — **Accepted.** The instinct is one cross-platform suite; it is not available, because the thing under test on the accessibility rows is `UIAccessibility`, `AccessibilityNodeInfo` and the DOM accessibility tree, which share no surface. So three things are shared one level up — a numbered capability catalogue, a text report grammar (`CONF <id> PASS|FAIL|SKIP`), and a generated matrix — and the test bodies deliberately are not. The first honest generation showed web graded on **8 of 28** claims, which is what drove [ADR-041](layer-5/ADR-041-one-host-core-split-at-the-zipline-seam.md).

- [ADR-041: One Host Core, Split at the Zipline Seam](layer-5/ADR-041-one-host-core-split-at-the-zipline-seam.md) — **Accepted.** Decided by spike, not taste: only **2 of 26** common host files import Zipline, and everything else — including the generated design-system bindings — compiled for `wasmJs` unmodified. A transport-free core gains a `wasmJs` target and becomes the one implementation everywhere; `dogwood-web` deletes `WebTree` and `WebBindings` (627 lines of second implementation) and keeps what is genuinely web-shaped. Built as a source set rather than two modules, which the ADR records as a correction to its own first draft. Web went from 8 graded claims to 27, and the page gained 474 KB — **not a regression**, because pre-split web linked no Material 3 and could render five layout widgets.

- [ADR-042: Numeric Ranges Are Declared on the Surface](layer-5/ADR-042-ranges-are-declared-on-the-surface.md) — **Accepted.** `@Range(min, max)` on a surface parameter, and the generator emits the clamping reader. The durable half of [ADR-035](layer-5/ADR-035-hostile-property-values.md): a hand-written clamp protects the property somebody thought of, and the next property with an enforced range and no clamp reintroduces the vector. Declared rather than inferred from a parameter's name, for the same reason `@Affordance` is.

- [ADR-043: Live-State Holders Are Declared on the Surface](layer-5/ADR-043-holders-are-declared-on-the-surface.md) — **Accepted.** [ADR-014](layer-5/ADR-014-live-state-holders.md) established the holder shape and left ~29 holders to pay for it by hand, twice each — once in the guest stub, once in the host binding. `@Holder` declares one, a registered shape says how it crosses, and the generator emits both sides; the **host mirror stays hand-written**, because what a holder does requires taste and does not grow without bound. Fail-closed: a `@Holder` on an unregistered type stops the build, because a guessed shape emits properties no host reads and the widget still renders. `FocusRequester` is the first, and holder properties follow absence-as-sentinel — sending them unconditionally would blank every text field on a client one dictionary version behind. Verified on a device: six requests, six actions, and a code update that neither loses focus nor takes the keyboard back.

- [Layer 4 ADR-012: Resynchronisation After a Rejected Batch](layer-4/ADR-012-resynchronisation-after-a-rejected-batch.md) — **Accepted.** [ADR-011](layer-4/ADR-011-a-batch-applies-whole-or-not-at-all.md) made a rejected batch survivable and left the screen frozen against a guest that had moved on. The host now clears its tree and calls `resynchronise()`; the guest snapshots its own state, disposes its composition and builds a new one, which emits the whole tree as creations because a fresh composition has nothing to diff against. Cleared **first**, on the user-interface thread, or the reply would be a second copy of every node.

- [Layer 4 ADR-013: Attributing a Pause Without Patching QuickJS](layer-4/ADR-013-attributing-a-pause-without-patching-quickjs.md) — **Accepted.** Phase 0 specified a patched native build to time `JS_RunGC` and it was never made; the ADR records that **the patch could not have answered the question anyway**, since the outlier is on a Pixel and the patch would have instrumented a development machine. `PauseWatcher` uses the public `InterruptHandler` instead: a collection shows as a gap between callbacks, and the heap separates it from scheduler preemption because QuickJS is primarily reference-counted. On both hosts measured, **the worst pause is not a collection** — the statement experiment 0.4 could not make. Neither reproduced the original 22.1 ms sample, so the caveat moves from "cannot be attributed" to "not yet run on the machine that produced it".

- [ADR-044: A Scroll Position Is Reported on a Quantum the Guest Declares](layer-5/ADR-044-scroll-position-is-a-declared-quantum.md) — **Accepted.** A guest could not scroll anything that was not a list: `Column` clips, and `VerticalList` wants items. [ADR-014](layer-5/ADR-014-live-state-holders.md) fixed a list's reporting quantum at the *item*, and a scrolling container has none — its offset is a length that changes every frame. So the **guest declares the quantum** and it crosses as an ordinary property, which bounds traffic rather than throttling it and makes the trade legible at the call site. **Both ends are reported exactly** whatever the quantum is, because a quantised offset equals the maximum only by accident and "am I at the bottom?" is the question a paginating guest asks — the sample measures 992 dp against a quantum of 40, so the naive version never fires. The end is asked for as an *intent*, since the maximum is host layout and a guest's copy of it is always stale. The device then produced a defect general to the whole pattern: **a report is edge-triggered and a replacement guest needs a level** — a container came back from a code update reading `offset 800dp of -1dp`, the offset right because it was saved and the maximum absent because it was only ever reported. `LocalGuestGeneration` fixes it for every mirror; `LazyListMirror` was checked and had survived by coincidence of tree churn rather than by design.

- [ADR-045: Web Page Weight — Where the Levers Are, and Which of Them Pay](layer-5/ADR-045-web-page-weight-where-the-levers-are.md) — **Accepted.** Phase 7's closing investigation, with a gate of "a measured saving, or a reason it does not pay" per line. **All four of the roadmap's lines are no**, each on a measurement of the shipped page rather than the spike modules: the design-system half cannot be deferred because *the split does not exist* (five Gradle modules compile to one WebAssembly module and Kotlin/Wasm has no code splitting); a registration seam has a **measured ceiling of 297 KB brotli** and is declined because a client linking a subset turns an impossible skew case into a routine one; Skiko has **grown** across all four available versions, so the pinned one is already the smallest; and a Document Object Model tier — the one lever that moves the number — is a second design-system implementation for the web, which [ADR-041](layer-5/ADR-041-one-host-core-split-at-the-zipline-seam.md) had just finished deleting. **The lever that pays was not on the list**: serving gzip rather than brotli costs 987 KB and 4.94 s on Fast 3G, more than three times the whole design system, for one server setting. Three quarters of the page is a prebuilt binary this project cannot shrink, configure or defer.

- [ADR-046: A Product Registers Its Own Dictionary Segment](layer-5/ADR-046-a-product-registers-its-own-segment.md) — **Accepted.** The gap the specification called item (c) of subsystem 9 and summarised in one sentence: "without (c) a guest can emit only raw Material 3, which no product team ships." `RenderNode` called one binding **by name**, so every mechanism around it — the lock, the affordance guard, skew reporting, the version vector — was parameterised by segment and had exactly one caller, which is a different thing from being general. Dispatch now goes through `DogwoodRegistry`; a product writes a surface, one `*Impl` per component and a segment identifier, and the generator emits both sides. Adding a second caller found the three places that had assumed one: the guest runtime's recording seam was `internal` (now public behind `@DogwoodGeneratedApi`, whose audience is generated code), generated code assumed it shared a package with the runtime, and a segment's Kotlin name and wire name were one field — which put the design system in the version map **twice under two spellings** the moment a binding named itself. The registry refuses a duplicate segment and an overlapping tag, the second being the failure a per-surface lock cannot see. Verified on a device with `samples/product-design-system`: Acme's components render in their own colours, `¥1299` by Acme's own currency rule, three taps crossing into a segment-2 handler. **The first attempt rendered nothing** — registration was in the wrong activity, and every component came out as an inert placeholder with no error, which is registration's failure mode in general.

- [ADR-047: The Generator Ships as a Gradle Plugin, and Consumption Is Proved From Outside](layer-5/ADR-047-the-generator-ships-as-a-plugin.md) — **Accepted.** [ADR-046](layer-5/ADR-046-a-product-registers-its-own-segment.md) proved the mechanism with a sibling project, which resolves by path, sees internal source sets and needs nothing published — so it demonstrated the mechanism and left the *claim* untested. The generator now ships as `io.github.teegarcs.dogwood.codegen`; a product writes a `dogwood { segment(…) }` block with two real decisions instead of fourteen command-line arguments, one of which had to be **omitted** or the engine's version vector was silently overwritten. `samples-standalone/umbra` is a separate Gradle build with no path into this repository at all, and `tools/standalone-check/run.sh` asserts what a green build does not imply — that bindings were generated, that they compiled, and that a lock was written. **Publishing found two defects nothing else could have**: adding a publishing `group` renamed the Kotlin/JavaScript module, `internal` declarations are name-mangled against that name, and every browser test in `dogwood-compose` died with `then_babg2s_k$ is not a function` — a clean build did not fix it, which is what said it was a naming problem rather than a stale one. And a sources jar *packages* a generated directory rather than compiling it, so `dependsOn` on the compilations was not enough.

- [ADR-048: The Real Guest Runs on the Web, and the Screens Are Shared](layer-5/ADR-048-the-real-guest-runs-on-the-web.md) — **Accepted.** The largest hole in the alignment story: `web-slice`'s guest was a hundred lines of hand-written JavaScript, so **no Kotlin/Compose guest had ever run in a Worker** and every web claim was graded against shared host code or a guest no product would write. The screens moved to `samples/slice-screens` and both entry points depend on them — `slice-guest` binds them to a Zipline service, `web-guest` drives them from a Worker, and the screens name no transport. In a real browser: **93 nodes** of the About screen composed in a Worker, 27 rendered, a tap answered on a host frame with `[[1,19,11,true],[1,19,12,1]]` — a live-state holder declared with `@Holder` crossing from a real Compose composition. A product's segment renders there too, once `product-design-system` gained a `wasmJs` target: **a product's design system must target every platform its hosts run on**, obvious once stated and invisible while every host was a Java Virtual Machine one. Three defects found, none where it looked — an `onmessage` shim resolving a *minified* name, a harness hunting for a shape only one guest produced, and a "broken bridge" that was the probe's own Chrome flags: without `--enable-unsafe-swiftshader` `requestAnimationFrame` never fires, so the host's frame pump never runs. The hand-written guest answers events synchronously and needs no frame, so nothing had ever depended on one arriving.

- [ADR-049: Surviving a Bad Publish](layer-5/ADR-049-surviving-a-bad-publish.md) — **Accepted.** Shipping without a store review is half a capability; **un-shipping** without one is the other half, and nothing had it. The delivery path survived a failure to *fetch* and not a payload that fetched perfectly and then did not work — whose worst shape is self-concealing, because a payload that crashes on launch erases by crashing every recovery mechanism that lives in memory. So an attempt is recorded and **persisted before the payload runs**: that single ordering is the whole design, and everything else is bookkeeping. A version that fails twice is quarantined and the last known good one is named; a publisher can stop a release from the manifest's **signed** metadata, signed because an attacker who could set it unsigned could disable an application through the channel that exists to secure its updates. "It loaded" is deliberately not success — a payload that throws on its first composition has loaded. The kill switch does not fall back, because a publisher may be disabling the *feature* rather than the build. A quarantined version that later works is forgiven, because a truncated download would otherwise make the guard the outage. Two defects the tests found: an off-by-one that ran a crashing payload **three** times when told two — caught by a test written as the crash loop it models rather than as three calls in a row — and a store that threw taking the launch down with it. Verified on a device, including the recovery round trip. **Staged rollout is explicitly not built**: `InstallCohort` gives a device a stable bucket a server could stage against, and the absence is a missing server rather than a missing capability.

- [ADR-050: The Authoring Check Rejects What Compiles](layer-5/ADR-050-the-authoring-check.md) — **Accepted.** Layer 1 has required this since its adversarial review and nothing enforced it. `animateFloatAsState` in guest code compiles, runs, animates, and crosses the boundary sixty times a second — **the screen looks correct**, and the bill arrives months later as a battery complaint about a screen nobody changed. Every other rule in this architecture degrades visibly; this one degrades into a screen that works, which is the whole argument for a check rather than a paragraph. `io.github.teegarcs.dogwood.guest` rejects per-frame animation APIs and resource loaders, joins `check`, and names the replacement for each — asserted by a test, because a rejection with no alternative is a rejection somebody works around. **Half the tests are about false positives**, which is the right proportion: the sample's About screen contains the forbidden API's name in a comment *about this rule*, so a naive scanner's first act is rejecting the documentation of the rule it enforces. Comments and strings are blanked character-for-character so line numbers survive. The pattern accepts a brace, which was a real gap — `withFrameNanos { … }` is a trailing-lambda call, so the first version missed the most important entry on its own list in its most common form.

- [ADR-051: A Holder That Answers](layer-5/ADR-051-a-holder-that-answers.md) — **Accepted.** The fourth holder shape, and the first whose report is a **reply**. The three before it run one way at a time: a target goes down, or a report comes up, and the two are independent. A snackbar is the first thing a guest asks for *and waits on* — `showSnackbar` suspends, and a user who tapped *Undo* gets their row back while one who let it time out does not; a guest that ignored the answer has written a notification. It needs no new protocol: the request is properties, the reply is an event carrying **the sequence it answers**, so two requests in flight cannot be confused. Two rules fall out of that, both because a snackbar resolves after the guest moved on — a reply nobody is waiting on is dropped, and a superseded request is answered as dismissed rather than left suspended forever. Verified on three targets and on a device. **The first three emulator taps reported a dismissal rather than an action**, which would read as a protocol bug and was the finger arriving during the snackbar's enter animation.

- [ADR-052: The Skew Containment Drill Runs on Every Client](layer-5/ADR-052-the-skew-drill-on-every-client.md) — **Accepted.** Section 6's three containment claims had been run end to end on **Android alone** for months. The rules are shared code; *reaching* them is each host's own composition, which is exactly the shape where a test that passes everywhere coexists with behaviour that works in one place. `run-ios.sh` and `run-web.sh` are the same five steps — install at version N, patch the surface to N+1, rebuild **only** the payload, read the screen, restore on every exit path — and neither reads the host's log, because a line saying "withheld" is the host agreeing with itself. iOS walks the accessibility tree in-process (`simctl` cannot dump a hierarchy); the web reads `getFullAXTree` plus each node's box model, and hashes `app.js` before and after because a host rebuilt alongside the guest is a drill that quietly tests nothing. **Each port found a defect on its first run.** The web host provided **none** of the composition locals its bindings read — every local has a default, so the page rendered perfectly and threw away every withheld control, unresolved token and clamped value into a `SkewReport` nothing reads; the expression cache was keyed to nothing rather than to a guest, and live-state mirrors had no generation. And iOS never registered the product design system, so Acme's three components were inert placeholders on the one client of four that neither depended on the module nor called `register` — a rule that module's own build file already stated, unapplied to the platform added after it.

- [ADR-053: The Manuals, and a Reference Nothing Can Contradict](layer-5/ADR-053-the-manuals-and-a-generated-reference.md) — **Accepted.** Four documents were missing and the one that existed had been **false for seven phases** — `developer-experience.md` declared the system unbuilt and described a check that does not exist, and nothing caught either, because no check reads prose. Three are written by hand: getting started, authoring (each rule with the reason it exists, because a rule whose reason is missing gets worked around), and operating (whose §6 lists what does *not* exist, since a runbook describing a capability nobody built is worse than none). The fourth is **generated**: a hand-written page about the components is a fifth thing that can disagree with the surface, and the generator already emits four artifacts from one parse precisely so the two ends cannot drift. It is written into the source tree beside the lock, because a reference generated into `build/` is a reference nobody opens, and it carries no prose about what a component is *for* — the parser does not read documentation comments, and a generator that invented that would be worse than one that omits it. A product asks for its own with one line; the standalone check asserts the file carries a widget tag rather than merely existing.

- [ADR-054: A Render Test That Returns Nothing Composes Nothing](layer-5/ADR-054-a-render-test-that-returns-nothing.md) — **Accepted.** Part 7 carried an unexplained result — a hostile value clamped and reported on the Java Virtual Machine and not on the web — recorded honestly, and the wrong conclusion drawn from a real observation. `runComposeUiTest` returns `Unit` on one target and `Promise<JsAny?>` on the other, and the framework awaits that promise **only if the test function returns it**. Every shared render test had a block body, so on the web the composition never happened: assertions after the call read an un-composed tree and assertions inside it were never observed at all. A deliberate `fail()` inside a discarded block was watched to **pass**, which is what settled it. Six files, 49 tests, green on the web while composing nothing — they passed because `unknownWidgetTags` is recorded by `HostTree.apply` rather than by composition, and because several assert an emptiness an un-composed tree satisfies perfectly. The clamp test was the only one that could notice, because it is the only assertion about something a *binding* records while drawing. There is no divergence in the clamp. There is no portable return type to declare either, so the guard is a grep with a reason attached, watched to fail on a reintroduced block body and run before the build on every pull request.

- [ADR-055: The Web Guest Gets Its Host's Services](layer-5/ADR-055-the-web-guest-gets-its-hosts-services.md) — **Accepted.** ADR-048 put the real guest in a Worker running the same screens as the mobile payload, and every summary since said so truthfully. The sample said the rest in plain words the whole time — *this client offers no services at all*, *surface revision 0 (unreported)*, *host clock unavailable*. It ran the same screens and ran them **blind**. A Worker boundary carries no object references, so the surface is split by *who can answer*: the Worker answers `log`, `clock` and `network` itself, one `start` message carries the entry point, launch parameters, feature flags, routes and segment versions before the first composition, and `analytics` and `navigate` go back one-way. The payload types live in the module both halves compile, because a hand-mirrored `data class` is a second place a shape is known. The Explore screen — which needs a launch parameter **and** a network fetch to render anything — renders on the web for the first time. It also made a **code update** possible, the normal case on this architecture and one this profile had never performed: snapshot the old guest, close its bridge, clear the tree, attach with the snapshot riding the start message. A new conformance group **J**, because the capability had never been graded anywhere. The remaining asymmetry is honest and recorded: `network` on the web is the browser's Content Security Policy, not Dogwood's default-deny allow-list.

- [ADR-056: The Engine Survives Code Shrinking, Watched Rather Than Hoped](layer-5/ADR-056-the-engine-survives-code-shrinking.md) — **Accepted.** No build had ever run under R8, and this stack is the shape a shrinker breaks: generated adapters, generated serializers, "renders nothing, says nothing" as the likely first symptom. The first minified run rendered, round-tripped and recorded skew with **zero** Dogwood-specific keep rules — the reflective surfaces belong to Zipline and kotlinx-serialization, which carry their own consumer rules — so none ship, on evidence rather than neglect. The proof is a standing target, not a smoke check: `testBuildType = "release"` points the whole instrumented suite at the shrunk APK permanently, and everything that *did* break (nine failures, one per run) was the test harness meeting a shrunk app, each fix documented at the rule that makes it. Renaming is off in the drilled build because it fails the harness before a single test runs; shrinking and optimization — the halves that eat serializers — stay on.

- [ADR-057: A Whole Product Outside the Repository](layer-5/ADR-057-a-whole-product-outside-the-repository.md) — **Accepted.** No build outside the repository had ever produced a *payload* — the standalone check proved the host half, and the unproven half is the half a product ships. Umbra is three modules now: its own surface, a signed payload against the published `dogwood-compose`, and a desktop host that renders it; the check's verdict is a render transcript, not a build, and its first run failed. **The first guest compilation outside the repository found a generator defect**: the classifier rejected any lambda containing `(Int)` as "indexed content" — behind an operator-precedence slip, guarding a case that cannot reach it — so `onChange: (Int) -> Unit`, the most ordinary shape a stepper can have, was silently unbindable, and Umbra's stepper had never been callable in its life. The audit's argument, made by the build.

- [ADR-058: A Parameter With a Default Is a Parameter Nobody Is Asked About](layer-5/ADR-058-protection-by-default.md) — **Accepted.** `ReleaseGuard` — half of what ADR-049 says this architecture sells — was wired in one host of five; every integration point existed, all behind `= null` defaults, and the shell sample a product copies did not opt in. The defaults are gone: `DogwoodShell` requires `releaseGuard` and `onRefused`, `null` is accepted as a written decision, and removing the defaults turned the gap into two compile errors — which is the entire argument. Every Zipline host rides the guarded path; the bare-delivery hosts call `succeeded` on mount, because a payload that throws on its first composition has loaded. The web host is the recorded remainder.

- [ADR-059: A Guest Crash a Host Can Read](layer-5/ADR-059-a-guest-crash-a-host-can-read.md) — **Accepted.** Run before built, and the evidence went both ways. Worse than the audit's finding: a crash in a guest effect never reached the host at all — no exception handler on the composition's scope — and the `{ throw it }` default was a trap watched to spring: the callback runs inside a Zipline service dispatch, where a throw is returned to the *guest* as the call's failure, so the crash boomeranged into the sandbox and the host looked healthy. Better: Zipline applies source maps at build time, so once routed, frames name real Kotlin files from a shipped size-optimized payload with nothing to deploy alongside. Attribution is file-level — functions stay minified, line numbers do not survive — which one-screen-per-file makes enough to start.

- [ADR-060: Bounds on a Runaway Payload](layer-5/ADR-060-bounds-on-a-runaway-payload.md) — **Accepted.** The containment story covered values, names, crashes and per-frame cost, and was silent about `while (true)` and unbounded allocation — neither of which an authoring check can catch. Every loaded guest now runs under `GuestLimits` (256 MiB, a five-second interrupt on any unbroken run of execution), QuickJS's own knobs reached through `Zipline.quickJs` and established from the artifact. On by default for ADR-058's reason; applied before any guest code composes, because a bound applied after the first slice began is a bound the first slice never had. The interrupt heuristic times the run it is inside of — polls arrive only while JavaScript executes, so a gap means a new slice. Watched at two levels, including a full-pipeline drill where the interrupt fired source-mapped to the stuck payload's own file; **the negative control hung rather than failed**, which is the finding in its purest form.

- [ADR-061: A Payload Declares the Dictionary It Needs](layer-3/ADR-061-a-payload-declares-the-dictionary-it-needs.md) — **Accepted.** The web refused a payload naming a dictionary it could not render before creating the Worker; the mobile clients had render-time containment only, which degrades so gracefully a user cannot tell it from a bug. A payload now declares `dogwood.segments` in Zipline's **signed** metadata, derived from the generator's own output rather than restated, and both `loadGuarded` and the shell's update path compare it before `start`. A payload declaring nothing still runs — containment stays for those. Graded as `B3` on a real emulator and simulator. Two defects found by running it, both a value read too early: the declaration resolved at Gradle *configuration* time and shipped a manifest describing the previous build's payload, and the client's own version map was captured at construction — which would have made a host that registered its bindings late refuse every payload naming them. Weaker than the web's by one step and said so: Zipline exposes no manifest-only fetch, so the check runs after module evaluation and before `start`.

- [ADR-062: A Signed Web Sidecar](layer-3/ADR-062-a-signed-web-sidecar.md) — **Accepted.** The sidecar was unsigned and the kill switch's own comment said the switch was only as trustworthy as its origin. It now carries a **detached** Ed25519 signature verified through `crypto.subtle` against keys the host passes in, over the bytes already fetched, **before the document is parsed** — so no field of an unverified document is ever read. Detached because an embedded signature must exclude itself from what it covers, and that canonicalisation disagreement fails silently and late. A missing signature is a refusal; `trustedPublicKeys` has no default and `emptyMap()` is the written way to keep the old posture; the rotation rule is Zipline's, mirrored. Ed25519 in `crypto.subtle` was probed, not assumed. Graded on a real browser five ways, including the control that an unsigned-posture host still runs the altered sidecar. Half of ADR-032's gap remains and is stated: the guest script is still fetched without an integrity check.

- [ADR-063: A Web Crash Carries Its Frames](layer-5/ADR-063-a-web-crash-carries-its-frames.md) — **Accepted.** Measured before built. A production webpack build mangles the names in a stack and keeps **exact offsets**, which is what a source map resolves — so the frames are worth carrying and the resolution belongs offline. The stack rides the existing `ERROR` envelope as a second paragraph (no revision; `onGuestFailure` defaults to dropping it), and the map stays a **build artefact** because a served map hands every reader the payload's source. Ten frames arrive from a real crash in a real browser; all ten resolve, the top one to the `error(...)` call. Found by looking: the map itself contains a position past the end of the file it names, so the tool reports it and names the nearest real mapping rather than inventing one. Upstream draft #4, unfiled.

- [ADR-064: The Tail Budgets' Headroom Was Parallelism](layer-4/ADR-064-the-tail-budgets-headroom-was-parallelism.md) — **Accepted.** An emulator cannot stand in for the gate device, which was already recorded; the question underneath had never been asked. Same emulator at four cores and at one: median ratio 1.93×, but the median is not the story — `p50` recomposition is flat (in one case *faster* at one core, which is a single-threaded interpreter losing cross-core scheduling) while every `p95`/`p99` degrades two- to sixfold. Concretely **`G1` is met at four cores and missed at one**, with nothing about the payload changed. The steady-state margin is real; the tail margin was four cores, so the gate device is *more* urgent — the opposite of what an emulator run is usually reached for. Sensitivity, never gate evidence, and the write-up says so three times.

- [ADR-074: A segment version has two authors, and a binding omits a default rather than quoting one](layer-5/ADR-074-a-segment-version-has-two-authors.md) — **Accepted.** Twenty-six of the generator's thirty-nine excluded components carried one reason: a default naming an `internal` symbol. A binding omits a host-default-only argument rather than quoting it, which needs no symbol at all — and two returned, not twenty-six, because the other twenty-four had a deeper reason the check was reporting over. Seven more were a name collision with an `internal fun MaterialTheme`. Then the consequence the plan missed: the generator got better at the *same* library version, so a segment version now carries the library's version and the generator's revision, and property tags come from the lock rather than from position.
- [ADR-075: A report says who moved the control, and only the code that moved it knows](layer-5/ADR-075-a-report-says-who-moved-the-control.md) — **Accepted.** Seven of the Material 3 tier's live-state types got shapes; the bound count went 105 to 111. The `byUser` field stopped being computed from the position and became structural: the effect that drives a control reports its own landing, the snapshot flow reports everything else. Computing it was watched to fail in both directions — a search bar reading as expanded partway through expanding told the guest a user did it, and dropping that emission deleted the only report a synchronous target ever produces. `CarouselState` was measured and left unbound: all three carousels have an indexed content slot behind the holder, so it unblocks nothing.
- [ADR-073: A generated tier derives its version and keeps its tags](layer-5/ADR-073-a-generated-tier-derives-its-version-and-keeps-its-tags.md) — **Accepted.** The generator stopped being told what version Material 3 is and reads it off the host's own compile classpath, which is what ADR-072 already claimed. Tags come from the lock, so a library release that drops a composable retires one tag instead of renumbering every tag after it.
- [ADR-072: The Compose surface is generated from the artifact it binds](layer-5/ADR-072-the-compose-surface-is-generated-from-the-artifact-it-binds.md) — **Accepted, M0–M1 of [`plans/generator-v2.md`](../plans/generator-v2.md).** Every coverage figure quoted here was the ceiling of a generator that did not exist. Generator v2 reads the `commonMain` sources of the exact artifacts the host resolves — established on the day: Material 3 is `1.9.0` under Compose Multiplatform 1.10.3, every module publishes a sources jar, and the common surface is **241** widget-shaped composables (171 in Material 3), not ADR-005's 445 over modules the host never links. The decisions that make it tractable: the host binding calls the real function and *quotes* the library's own default expression for anything the guest omitted (`Button`'s nine defaults are all public API), so the generator never evaluates a default; a type the small mapping table cannot cross is a parameter the guest cannot set rather than a component it cannot call; overloads are told apart by parameter names; generated tiers take segment identifiers downward from 255 with `LAST_PRODUCT_SEGMENT = 200` refused past; the tier is a separate module registered explicitly so the page-weight question in M3 is a measurement. The primitive tier stays.
- [ADR-071: The coordinates are a namespace somebody owns](layer-5/ADR-071-the-coordinates-are-a-namespace-somebody-owns.md) — **Accepted.** Every artifact was coordinated `dev.dogwood` because it reads well, and nobody owns it: Maven Central verifies namespace ownership, so publishing would have meant buying and renewing `dogwood.dev`. Making the repository public turned that from an inconvenience into a getting-started guide a stranger cannot follow. The group is now `io.github.teegarcs`, which Central grants on GitHub identity alone, and the two plugin identifiers move with it because a plugin marker's group **is** its identifier. Artifact names, Kotlin packages (`dev.dogwood.*`, deliberately) and the project's name are unchanged. Thirty-five files, no Kotlin source but comments, and the reason it was that cheap is that pinning `outputModuleName` had already decoupled the emitted module names from the group — a pin added after a group change once broke every `internal` call site, and its first real test was this one. Taken now because a group rename after the first publication breaks every consumer's build instead of nobody's.
- [ADR-070: Every shipping platform is consumable, and the Worker guest is a library](layer-5/ADR-070-every-shipping-platform-is-consumable.md) — **Accepted.** Read per platform, one of three was consumable from outside: `dogwood-web` had no publishing coordinates at all, the Worker transport was 416 lines in a sample a product would have copied, and no build outside the engine had ever resolved the iOS artifacts. Now `dogwood-web` publishes with its module name pinned; `runInWorker` in `dogwood-compose` is the transport (bridge testable on Node, envelope still a mirror defended by the handshake); Umbra's design system is multiplatform with every target the host has, plus three probes — a WebAssembly page resolving the wasm-js variant, a Worker payload from the same screens, a linked iOS framework — and `tools/standalone-check/run.sh` runs all of it. The first iOS link outside the engine ran the Kotlin/Native cache out of memory, which is now a written requirement rather than a surprise. The same Umbra carries the day's other two proofs: an enumeration decoded into the design system's own type, and a pill composed in the payload from the primitive tier.
- [ADR-069: The primitive tier is the lever](layer-5/ADR-069-the-primitive-tier-is-the-lever.md) — **Accepted.** The owner's goal is "anything Compose offers without an app release", and in a tag-based protocol the only way that is ever true is ADR-006's rule — compose it in the payload from existing pieces — which was only as strong as the pieces: five widgets with no arrangement or alignment, text with no weight or overflow, twelve modifiers with no `clickable` outside `Row`. Segment 0 grew on every host at once: `clickable` on any node carrying its handler by element index (the mechanism animation completions already used, renamed `ELEMENT_EVENT_BASE`), arrangement and alignment on `Column`/`Row`/`Box`, six text overrides, and fifteen modifiers (border, offset, shadow, per-side padding, size bounds, semantics, test tag, and more), every one absent-by-default and every throwable value clamped. Layout version 2, so a version-1 host refuses rather than renders a screen nobody can tap. +4,283 bytes brotli on the web. Twenty-two tests across Node, the Java Virtual Machine, Chrome and the iOS simulator, each watched to fail first; the first run of `aspectRatio` found a clamp that caused the crash it existed to prevent.
- [ADR-068: The generator refuses what it cannot bind, and a surface may declare an enumeration](layer-5/ADR-068-the-generator-refuses-what-it-cannot-bind.md) — **Accepted.** A production review ran a probe surface through the real generator and found that a component with a `List<String>` parameter was dropped from both ends with the build green (ADR-006 had promised a failure for thirteen days), and that an enumeration parameter — a design system's most common non-primitive shape — was accepted and emitted as code that did not compile. Now: an unbindable component fails the build before anything is written, naming the parameter, the reason and the allowed types, with `allowUnbindable` as the audit-only escape; a surface may declare `enum class`, both ends get a copy (or the adopter's own via `@Implementation` on the enumeration), the entry **name** crosses rather than its ordinal, an unknown name degrades to the default and is reported as `UNKNOWN_ENUM_VALUE`, and the lock treats entries as append-only. `Long` and `Double` gained the readers they never had. Proven on the Acme sample across the Java Virtual Machine, WebAssembly and iOS.
- [ADR-067: The Surface Names Its Implementation](layer-5/ADR-067-the-surface-names-its-implementation.md) — **Accepted.** The generated binding called `${name}Impl` by convention, which for an adopter with an existing design system is a managed wrapper whose whole body is a call-through. Two facts made removing it cheap: the generated call already uses named arguments, and the surface is parsed rather than compiled, so `@Implementation("fully.qualified.Name")` can point the binding at the adopter's own composable directly — per component, host-side only (the dictionary encodings of a bound and unbound component are identical, by test), with the contract relocated to the host compiler rather than weakened. A non-literal target is refused at parse, because half-resolving one would generate calls to wrong names silently. Proven to render, not merely compile: Umbra's `UmbraChip` has no wrapper anywhere and the standalone check requires its transcript line; its two siblings keep wrappers on purpose, because a real surface mixes both — the wrapper earns its keep exactly where a wire type needs mapping.

- [ADR-065: Two Teams Need Two Shells, and Nothing Else](layer-5/ADR-065-two-teams-need-two-shells-and-nothing-else.md) — **Accepted.** No engine machinery, which was the plan's own rule. Two independently built, signed and versioned payloads in one application, with cache directory, guard file, dispatcher and interpreter separate; no shared warm pool and none proposed. The cost is **disk and it does not amortise** — 1.15 MB for a payload that draws three nodes, because the two are separate Zipline containers sharing nothing. The lock conflict was run, not described: two branches both claiming tag 24, the safe resolution (reset the lock to the *merge base*, never hand-merge generated JSON), and the refusal when you get it wrong. It also found a hazard the lock does **not** catch — the version number merges cleanly, so a payload published from an unmerged surface branch declares a version that will mean something else once it lands. Hence a written rule rather than a mechanism: publish from the integration branch, never from a surface branch.

### Open — no ADR yet

Decisions already reflected in the specifications that require an ADR before implementation, per `AGENTS.md` section 3:

- **No per-frame state in the guest.** Animation targets, scroll offset, gesture recognition, and text-field edit state live host-side. Determines which Compose APIs are bindable at all; blocks Layer 4 Milestone 5.
- **The `Modifier` representation.** Dogwood's tagged type, `then()` semantics, and scope-aware tags. Highest-leverage deliverable — 62.2% of the widget surface depends on it. Written jointly with the deferred-expression grammar, whose values modifier arguments carry.
- **The animation protocol.** Declarative targets, springs and easings, interruption semantics, completion events, time-varying `Modifier` values. Added by ADR-005; blocks the first animated production screen.
- **The resources and assets protocol.** Uniform Resource Locator (URL)-keyed images with placeholder/error slots, icon dictionary, fonts, localized strings. Added by ADR-005; blocks the first production screen on the generated-tier path (a registered `AsyncImage` covers it under design-system-first — ADR-006).
- **Host services, entry points, and host-registered components.** Launch contract, versioned service surface, per-module dictionary segments for registered components (ADR-006). Added by ADR-005; its Phase 1 seed is ADR-004 §2.5.
- **The live-state mirroring protocol.** Per holder, with a conflict rule.
- ~~The `Change`/`Event` protocol shape~~ — **now proposed as [Layer 4 ADR-004](layer-4/ADR-004-change-event-protocol-v0.md)** (provisional v0, binding for Phase 1; v1 revision fed by Phase 1 measurements).
- **Host composition versus imperative applier.** Redwood mutates widgets imperatively and does not recompose; Layer 5 currently specifies a snapshot mirror. Benchmark before Layer 5 Milestone 3 commits.
- **Dropping the ZiplineLoader fork**, and Layer 3 owning interpreter instantiation.
- **Surface source: Kotlin frontend over metalava**, forced by metalava carrying no default expressions.
- **Policy on binding `@Deprecated` APIs** — 6.1% of the measured surface.
